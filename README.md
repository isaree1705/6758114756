# Idea Board

A responsive Next.js + TypeScript app using Supabase PostgreSQL, designed for Vercel Hobby. Visitors can share ideas and vote without accounts or payments.

## Architecture and security

The browser calls Next.js Server Actions. Only the Node.js server connects to PostgreSQL, using the dedicated `idea_board_app` role. No Supabase API key, service-role key, or database password belongs in client-side code. The connection helper is guarded with `server-only` and requires the restricted username. Queries use parameterized SQL and verified TLS.

Both tables have RLS enabled. Browser roles (`anon` and `authenticated`) have no table privileges. The app role can SELECT and INSERT under explicit RLS policies; it cannot UPDATE, DELETE, or bypass RLS. Supabase administrators retain administrative access.

Each voter gets an HMAC-signed UUID in an HttpOnly, SameSite=Lax cookie (Secure in production). The `(idea_id, voter_id)` primary key prevents duplicate votes, including concurrent inserts for the same identified voter. Clearing cookies, using a different browser, or racing initial requests without a cookie can produce another identity. This is browser identification, not proof of a unique person. Rotating the signing secret invalidates existing voter cookies. No authentication or abuse prevention service is included in this first version.

Titles, descriptions, nicknames and votes are public through the app. Voter identifiers and credentials are never rendered to clients. React escapes user content. The board shows the 100 newest ideas and calculates vote counts from stored votes.

## 1. Database setup

Create a free Supabase project. For a **new** project, run `supabase/schema.sql` once in its SQL Editor. It creates the tables, constraints, restricted role, grants, and RLS policies in a transaction. If you already completed guided steps 2 and 4, **do not rerun it**: your schema is already installed.

Set a separate, randomly generated password of at least 32 letters and numbers on `idea_board_app` using Supabase SQL Editor:

```sql
alter role idea_board_app password 'REPLACE_WITH_YOUR_GENERATED_PASSWORD';
```

Replace this placeholder privately; never save the actual command/password in Git or chat. If you completed guided step 5, keep the password you already set.

## 2. Server environment variables

In Supabase, choose **Connect → Transaction pooler**. Use the displayed pooler host, port `6543`, database `postgres`, and project reference. Replace the default `postgres.PROJECT_REF` username with `idea_board_app.PROJECT_REF`, and use the app role password, not the project's administrator password.

For local development, copy `.env.example` to `.env.local` and replace its placeholders:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | `postgresql://idea_board_app.PROJECT_REF:APP_ROLE_PASSWORD@POOLER_HOST:6543/postgres` |
| `VOTER_COOKIE_SECRET` | A separate, random secret of at least 32 characters; use 64 random letters and numbers from a password manager |

Use your actual Supabase pooler host and project reference. URL-encode the password if it contains URL special characters. These are **server-only** variables; never prefix them with `NEXT_PUBLIC_`. `.env.local` is ignored by Git. No Supabase publishable key is needed for this server-only approach.

Transaction pooling uses one connection per app instance with prepared statements disabled. Keep certificate verification enabled. If the connection fails, check the pooler host, role username, password, project status, and Supabase network restrictions. Never disable TLS verification to bypass a certificate error.

## 3. Local development and checks

Use Node.js 22.18 or later (Node 24 is also supported). From the project directory:

```sh
npm ci
npm test
npm run build
npm run typecheck
npm run dev
```

In a local terminal, open the address printed by Next.js. This cloud onboarding interface does not offer a live web preview; screenshots can be generated by the agent instead.

Without credentials, the app displays a clear disconnected state with submission disabled. The build does not require database credentials. A missing/unreachable database does not display a misleading empty board, and connection errors are not exposed to visitors.

Tests cover signed voter cookies, malformed input, and database permission/constraint behavior using an isolated embedded PostgreSQL instance. They do not connect to your Supabase project.

## 4. Deploy on Vercel Hobby

1. Save the project files to your GitHub repository, excluding `.env.local`.
2. Sign in to Vercel, choose a personal Hobby workspace, then **Add New → Project** and import the repository. Authorize access to this repository if prompted.
3. Keep the detected **Next.js** preset and repository root directory. Use Node.js 22.18+ or 24.x, `npm ci` for installation, and `npm run build` for building. Leave the output directory at its default.
4. In the project's environment-variable settings, add `DATABASE_URL` and `VOTER_COOKIE_SECRET` with the private values prepared above. Enable them for Production. Only enable Preview if preview deployments should access this same database; a separate development database is preferable for previews.
5. Deploy. If variables are added or changed after a deployment, redeploy to apply them. No local development server must remain running.
6. Open the HTTPS deployment address and run the smoke check below. Keep the same cookie secret across deployments so existing voters retain their identity.

No paid add-ons or Vercel integrations are required. Hobby and Supabase Free quotas and eligibility apply; this guide does not enable paid services.

## 5. Verify the live connection

1. Submit an idea with a title, description, and nickname. Confirm it appears with 0 votes and is stored in Supabase's `ideas` table.
2. Vote once. Confirm the count becomes 1 and a row appears in `votes`.
3. Refresh the page. Confirm your vote remains marked and the button is disabled. Retry the same `(idea_id, voter_id)` insert privately in SQL Editor: it must fail with a duplicate-key error. Do not share the voter ID in chat.
4. Open another browser profile. Confirm it sees the idea/count, and can vote as another identified voter.
5. Check narrow-screen layout and form validation. If the board shows an outage, verify the server environment variables and Supabase connection before calling the deployment ready.

Live Supabase behavior must be verified after credentials are configured. A successful build or isolated database test alone does not prove the deployed connection works.
